DELL DEVICE_TYPE GATEKEEPER PRINCIPLE

Purpose & scope
This document defines the Dell-only, declarative gatekeeper rules for the cleaned spec fields
"line_type" and "device_type" under semantic model v2.1. It is normative documentation aligned
with Dell Design Freeze v1 and the Dell Cleaned Spec principle. It introduces no new behavior,
logic, or inference.

Normative core principle (v2.1)
- line_type MUST be assigned to every row using the canonical high-level classes.
- device_type MUST be assigned to every row as a non-empty detailed row kind.
- Both fields MUST be deterministic and MUST NOT rely on free-text interpretation.

Canonical line_type classes (v2.1)
- SYSTEM
- PHYSICAL_COMPONENT
- CONFIGURATION
- SOFTWARE_LICENSE
- SERVICE
- META

Canonical device_type mapping (minimum)
- SYSTEM: device_type MUST be SERVER (canonical; SYSTEM MAY be used only if documented elsewhere).
- PHYSICAL_COMPONENT: device_type MUST be one of
  CPU, RAM, SSD, HDD, PSU, RAID_CONTROLLER, NIC, GPU, HEATSINK, FAN, CHASSIS_PART.
- CONFIGURATION: device_type MUST be CONFIGURATION.
- SOFTWARE_LICENSE: device_type MUST be SOFTWARE_LICENSE.
- SERVICE: device_type MUST be SERVICE.
- META: device_type MUST be META.

Module Name role clarification (Dell-only)
- Module Name is NOT a line_type or device_type inference signal.
- Module Name MUST NOT be used to guess or infer line_type or device_type.

Safety-first default (fallback rule)
- If the device_type cannot be determined deterministically:
  - device_type MUST be set to UNCLEAR (non-empty fallback).
- line_type MUST still be assigned deterministically using structural rules only.

Determinism guarantee
- The rule forbids free-text heuristics and ML/probabilistic behavior.
- The rule requires a non-empty, deterministic device_type for every row.

Explicit non-goals
- No changes to Dell pipeline behavior or stage contracts.
- No new classification logic or inference rules.
- No reinterpretation of Dell Design Freeze v1.
- No semantic use of Module Name.
