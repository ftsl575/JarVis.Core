PRINCIPLE: CLEANED SPEC — DELL

ЦЕЛЬ
Cleaned spec предназначен для быстрого и однозначного понимания того,
КАКИЕ КОМПОНЕНТЫ ФИЗИЧЕСКИ УСТАНОВЛЕНЫ В СЕРВЕРЕ ИЛИ ПОСТАВЛЯЮТСЯ С НИМ.

ОСНОВНОЕ ПРАВИЛО
В cleaned spec по умолчанию отображается ТОЛЬКО состав поставки,
а не состояние, режимы или подтверждения конфигуратора.

КЛАССЫ ДАННЫХ

1. ФИЗИЧЕСКИЕ КОМПОНЕНТЫ
Включаются в cleaned spec и идут первыми:
- CPU, Memory, RAID Controllers, NIC, GPU, Drives, PSU, Chassis parts
- Всё, что физически установлено или лежит в коробке

2. НЕФИЗИЧЕСКОЕ (ПО / ЛИЦЕНЗИИ / СЕРВИСЫ)
Отображаются отдельным блоком ниже физики:
- ОС, лицензии, iDRAC features
- Warranty, support, deployment services

3. ОПИСАНИЕ КОНФИГУРАЦИИ (СЛУЖЕБНОЕ)
По умолчанию НЕ является частью cleaned spec:
- No X / Disabled / Decline
- Configuration / Features / Modes
- RAID / Drive / PSU / BIOS configuration
- Regulatory, Shipping, Documentation

Допускается:
- только как служебный хвост
- для диагностики и редких случаев
- не используется в инвойсах и основных документах

ПРИНЦИП ОТСЕЧЕНИЯ
Если строка описывает СОСТОЯНИЕ, РЕЖИМ или ПОДТВЕРЖДЕНИЕ,
а не ФИЗИЧЕСКУЮ ПОСТАВКУ — она не должна мешать просмотру состава сервера.

DELL CLEANED SPEC SEMANTIC MODEL V2 (NORMATIVE)
Этот раздел формально определяет Semantic Model v2 для Dell cleaned spec.
Он не меняет поведение Stage 1–4 и не вводит эвристик; он закрепляет смысл.

A) Обязательная семантическая типизация (NORMATIVE)
- Для всех нормальных/повторяемых строк cleaned spec MUST быть явный semantic type.
- Минимально MUST быть типизированы строки классов:
  SYSTEM, PHYSICAL_COMPONENT, CONFIGURATION, SOFTWARE_LICENSE, SERVICE.

B) Определение device_type (NORMATIVE)
- device_type — это семантический тип СТРОКИ cleaned spec.
- device_type НЕ является только системным якорем.
- device_type НЕ ограничен только SYSTEM-строками.

C) Политика Unclear (NORMATIVE)
- Unclear НЕ является допустимым значением по умолчанию.
- Unclear НЕ допускается как нормальный/повторяемый финальный результат.
- Unclear допускается ТОЛЬКО как временный fallback для строк, требующих новых детерминированных правил.

D) Явное разделение категорий (NORMATIVE)
- PHYSICAL_COMPONENT: CPU, RAM, SSD, HDD, PSU, RAID controller, NIC, GPU, heatsink, fan, backplane, chassis parts.
- CONFIGURATION: режимы, возможности, лимиты, “No X”, конфигурация шасси, BIOS/RAID настройки.
- SOFTWARE_LICENSE: ОС, лицензии, management software.
- SERVICE: гарантия, поддержка, deployment services.

E) Минимальный набор semantic types (NORMATIVE, НЕ РАСШИРЯТЬ)
- line_type (high-level): SYSTEM | PHYSICAL_COMPONENT | CONFIGURATION | SOFTWARE_LICENSE | SERVICE | META.
- device_type (row semantic type):
  - SYSTEM: SERVER (или уже существующий системный токен, используемый в документации).
  - PHYSICAL_COMPONENT: CPU, RAM, SSD, HDD, PSU, RAID_CONTROLLER, NIC, GPU, HEATSINK, FAN, BACKPLANE, CHASSIS_PART.
  - CONFIGURATION: CONFIGURATION.
  - SOFTWARE_LICENSE: SOFTWARE_LICENSE.
  - SERVICE: SERVICE.

NON-COMPLIANCE NOTE (NORMATIVE)
Выходные данные, где большинство строк имеют device_type = Unclear,
являются НЕСООТВЕТСТВУЮЩИМИ Semantic Model v2 и допускаются только как временный fallback.

КОЛОНКА "Module Name" (НЕАВТОРИТАТИВНАЯ)
Назначение этой колонки — только информационное отображение (display-only).

1. Название колонки
- Точное имя: "Module Name"

2. Источник
- Прокидывается из входных данных Dell при наличии.

3. Статус
- НЕАВТОРИТАТИВНАЯ.
- Только информационное / display-only поле.
- Не используется для line_type или device_type.

4. Гарантии
- Наличие или отсутствие НЕ влияет на:
  - line_type
  - device_type
  - grouping
  - segmentation
  - логику нормализации
- Никакой эвристической интерпретации.

5. Поведение при отсутствии
- Если "Module Name" отсутствует или пустая:
  - cleaned spec остаётся детерминированным
  - применяется существующая логика идентификации и нормализации без изменений
  - нет ошибок и ветвления по этому полю

6. Соответствие Design Freeze
- Эта документация НЕ изменяет и НЕ расширяет Dell Design Freeze v1.
- "Module Name" документируется только как информационное поле.
